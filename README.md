# ait · 点睛

在页面上画个圈，说一句话，改动落到源码上。

面向**手里有源码、以开发模式运行项目**的人。不内置模型，复用你已经在用的编码 Agent（Trae / WorkBuddy / Cursor / Claude Code）。

> 当前仓库是 **交互验证 Demo**，不是可日常使用的产品。语音与源码改写尚未接入，详见[状态](#状态)。

![Demo](demo/preview.png)

## 问题

改一处界面，成本不在改，而在到达：找到那个元素、说清改哪、把上下文搬进对话、再回来确认。

传统路径是"审查元素 → 抄 selector → 切到编辑器 → 打字描述 → 粘贴 → 回来刷新"。六步，每一步都要离开视线。

点睛把这条路径压缩成两个动作：**用鼠标指，用嘴说。**

## 体验 Demo

需要 Chrome，以及一个能跑本地静态服务的环境。

```powershell
cd demo
.\start.ps1
```

脚本会起服务（5199 端口）并打开浏览器。然后：

1. 打开 `chrome://extensions`，开启开发者模式
2. 「加载已解压的扩展程序」，选择 `demo/extension`
3. 回到页面刷新，点右上角圆形「点睛」按钮
4. 在页面元素上拖一个圈，在输入条里打字回车（模拟说了一句话）
5. 说「开始改」，目标元素真的改变样式

Chrome 137 正式版起禁止 `--load-extension`，扩展只能手动加载。

## 一条链路

画圈 → 说一句 → 命中元素与源码位置 → 浮窗成稿 → 提交上下文包 → 看到改动生效。

- **画圈不触发页面行为**：捕获阶段接管鼠标事件并 `preventDefault`，不产生 `click`
- **命中靠采样**：包围盒打 8×8 网格，`elementsFromPoint` 计票，贴合实际形状
- **语义匹配**：口述文本与候选逐项打分（文本 60 / aria 45 / 语义 20 / 票数 15 / 源码可定位 5）
- **源码位置**：`data-ait` 属性携带 `src/components/ProfileCard.vue:45:7`，由构建期插件注入
- **上下文包**：目标、指令、草稿、`trace_id` 关联的运行时日志，一次交清
