## 1. 分工与职责

**① 负责"指哪、说什么"；② 负责"对应哪段代码、交给谁改、改得对不对"；③ 是被修改的对象。**

三层各司其职，互不越界。② 不内置编码模型，只做上下文与通道的转换。

| 层 | 职责 | **禁区** |
|---|---|---|
| **① Chrome 扩展**<br>交互入口 | 画圈/框选、DOM 采集、端侧语音（sherpa-onnx）、浮窗与交互状态、请求拦截注入 trace id | 不读写源码、不执行命令、不持有任务状态、不内置编码模型 |
| **② 本地桥**<br>上下文与通道中枢 | 接收标注、DOM→源码映射、日志关联、提示词组装、**通道适配（MCP server / ACP 投递 / 剪贴板）**、应用补丁、执行校验与测试 | 不做 UI、不访问麦克风、不内置编码模型、不产生推理成本 |
| **③ 前端工程** | 源码、配置、dev server、HMR、测试 | — |

**② 的角色是桥，不是执行者**：模型由用户已装的 Agent 提供，② 只负责把"指哪+说什么"翻译成 Agent 能精确执行的上下文，并把 Agent 产出的补丁安全落地。

**状态归属**：任务生命周期（修改、校验、回滚）位于②，①仅作为其显示端。①因此退化为纯 UI，可随时刷新重连。

**形态限制**：① 只在浏览器内运行，切换至 IDE 或终端后没有浮窗与语音。任务状态位于②，可经②查询进度，后续可增加 CLI 在 IDE 侧查看。

## 2. ② 为何必须是本地进程

以下五项能力扩展无法提供，且均为产品必需：

| 能力 | 扩展的限制 |
|---|---|
| 读取源码并定位到文件行号 | 仅能访问 DOM，无法访问磁盘上的 `.vue` / `.tsx` |
| 执行 `tsc --noEmit` / eslint / 测试 | 无进程执行权限（native messaging 仅可与已注册宿主通信） |
| 创建 git 快照与回滚 | 同上 |
| 读取后端日志文件 | 沙箱内无法访问任意路径 |
| **作为 MCP server 供 Agent 拉取** | MCP 需要 stdio 或监听端口，扩展两项均无法提供 |

因此②不是可选优化，而是**功能必需**。

> 扩展可以直接 `fetch('http://127.0.0.1:PORT')`——service worker 声明 `host_permissions` 后免 CORS，无需 content script 中转。这解决的是①→②的方向；②→Agent 的方向由 MCP 与 ACP 承担。

## 3. ② 的装配方式

使用②的人不具备前端知识，不会修改 `vite.config.ts`。因此②必须自行完成全部装配。

```
项目根目录
└── npx ait
      ├─ 识别项目类型（Vite / 其他）
      ├─ 以代码方式加载原有 dev server 配置，追加 AIT 插件
      │    createServer({ configFile: 'vite.config.ts', plugins: [aitPlugin()] })
      ├─ 启动本地 WS 服务（挑选空闲端口）
      ├─ 写入已装 Agent 的 MCP 配置（合并，不覆盖既有条目）
      └─ 打印配对 token（扩展一次性粘贴）
```

**用户不需要修改任何项目文件。**

收益：

- 单条命令，无需全局安装（`npx` 按需拉取）
- 可直接获取项目根目录、git 仓库与 dev server 端口
- 无需开机自启、系统托盘或端口冲突处理
- 切换项目仅需在新目录启动，天然实现多项目隔离
- 通过代码追加插件，保留 `data-ait` 注入能力的同时免除用户配置

**Vite 插件形态保留为可选**，供希望接入自有 `npm run dev` 的用户使用。**代价**：`npx ait` 需覆盖 Vite 的启动路径，非 Vite 项目（webpack / Vue CLI）暂不支持，先实现 Vite 版本。

## 4. ② 的核心能力

### 4.1 DOM → 源码映射

**问题**：运行时反射获取的组件名是压缩产物（实测 `Gs`、`pz`、`n`），不具备可用性；React 19 又收紧了内部 Fiber 访问。

**方案：编译期注入，不做推断。**

Vite 插件在 transform 阶段为每个模板元素注入属性：

```html
<button class="edit-btn" data-ait="src/components/ProfileHeader.vue:45:7">编辑资料</button>
```

- **Vue**：通过 SFC 编译器的 `nodeTransforms` 获取元素在源文件中的行列号
- **React**：由 babel/swc 插件为 JSX 注入同一属性
- **仅在 dev 注入**，build 不注入 → 生产包无污染

准确率 100%，不依赖框架内部结构，成本为一个插件加一行配置。

降级：无 `data-ait` 的元素（动态创建、第三方组件）退回 CSS selector 与文本。**既不伪装成功，也不因此中断。**

### 4.2 日志关联

日志按三级递进过滤：

```
trace 命中（扩展为同源请求注入 X-AIT-Trace-Id，后端日志携带同一 id）
  → 路由 + 60s 时间窗
  → 压缩为「时间/方法/路径/状态码/一句话」，上限 10 条
```

进入模型前必须脱敏（手机号、身份证、Bearer、token 字段）。

**该能力需后端配合**（在日志中携带 trace id）。若后端无法修改，降级为按路由与时间窗推断，精度下降但不阻塞流程。

### 4.3 提示词与项目上下文

②具备完整项目视角，提示词应在此组装，而非在扩展内：

- 项目类型（Vue / React）、路由、当前文件
- 目标元素的源码位置与周边上下文（读取该文件前后 30 行）
- 日志证据
- 用户口述指令（已清洗）
- 约束：仅修改目标文件、不改动依赖、保持既有代码风格

### 4.4 执行

```
接收任务
  → git stash 或临时 commit 创建快照
  → 通过通道交给用户已装的 Agent（见 4.5）
  → 解析返回的 patch
  → 写盘前执行 tsc --noEmit / eslint
  → 通过 → 写盘 → Vite HMR 自动生效
  → 失败 → 回滚快照 + 将错误回传浮窗
```

**不内置模型。** ② 不持有 API Key、不产生推理成本、不锁定 Agent 厂商。

### 4.5 通道适配

同一个上下文包，按目标 Agent 的能力分三路投递：

| 通道 | 实现 | 触发方式 | 约束 |
|---|---|---|---|
| **ACP 直连** | `POST /api/v1/acp/connect`（loopback 免鉴权）→ 拿 `connectionId` + `sessionToken` → SSE 收流式回复 → `prompt` | 说「开始改」后**主动推入对话** | 客户端仅为活跃会话维持 session，空闲回收时需重试与降级 |
| **MCP server** | ② 暴露 `get_ait_context`（Resource/Tool）+ `apply_patch` | Agent 侧说一句固定话术后**主动拉取** | 客户端不开放注入接口，无法主动推送 |
| **剪贴板** | 上下文序列化后写入剪贴板 | 用户手动粘贴 | 无需任何配置，作为最终降级 |

**能力差异必须显式呈现，不做伪装**：只有 ACP 能推送，MCP 只能拉取。扩展浮窗需按实际通道显示不同的完成提示（"已发送" vs "上下文已就绪，请在 Agent 中说『按我选的改』"），否则用户会以为消息丢了。

**MCP 工具设计**（保持精简，避免 schema 常驻成本）：

| 名称 | 类型 | 作用 |
|---|---|---|
| `get_ait_context` | Tool | 返回最近一次标注的完整上下文（含目标源码位置、日志、口述原文） |
| `apply_patch` | Tool | 提交补丁，经快照与校验后落盘 |
| `ait://current` | Resource | 当前标注的只读快照，供 Agent 预读 |

**通道选择由 ② 自动完成**：检测本机运行的 Agent → 优先 ACP → 其次 MCP → 最后剪贴板。不做用户配置项。

## 5. ① 的语音栈

语音在 ① 内部闭环，② 与 Agent 均不接触音频。

### 5.1 运行位置

| 位置 | 能否使用 | 原因 |
|---|---|---|
| service worker | ✗ | 无 DOM，30 秒空闲即被回收 |
| content script | ✗ | 运行于页面上下文，第三方页面的 CSP 与资源均可被篡改 |
| **offscreen document** | ✓ | `reason: USER_MEDIA` 不会被自动关闭，具备 WebAudio 与 Worker |

**必须单线程 WASM。** 多线程依赖 `SharedArrayBuffer`，而它要求 COOP/COEP 响应头——第三方页面无权添加，`chrome-extension://` 页面也无法声明。

后果：中文流式识别实时率仅 0.5–0.9×，无法支撑逐字上屏。因此界面不做实时字幕，改为句末整句呈现。

### 5.2 四个部件

采用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0，ONNX Runtime，官方提供 WASM 构建）。选择依据不是模型数量，而是四个部件可独立替换。

| 部件 | 模型 | 职责 | 生命周期 |
|---|---|---|---|
| VAD | silero-vad | 判定句末：700ms 静音由端点检测触发，不依赖定时器 | 常驻 |
| KWS | 开放词表关键词检测 | 待机时仅运行 KWS，命中「点睛点睛」后才启动 ASR | 常驻 |
| ASR | 流式 Zipformer（14M 中英）/ SenseVoice | 句末整句输出 | 唤醒后加载 |
| 热词 | contextual biasing | 组件名与字段名入热词表，降低标识符错识 | 随 ASR |

### 5.3 状态与资源

```
待机 ──KWS 命中──▶ 聆听 ⇄ 句末上屏（进草稿）
                    │
                    └── 静默 30s ──▶ 待机
```

常驻仅 VAD 与 KWS（低功耗），ASR 在唤醒后加载、连续静默后卸载。这是「常驻监听」在笔记本上成立的前提。

### 5.4 模型与配置

- **模型即配置**：换模型只换文件，不改代码。轻量（Zipformer）与准确（SenseVoice）按机器性能切换，不对具体模型作长期承诺
- **首次下载**：百 MB 级，加载数秒。int8 量化有精度损失，未进热词表的标识符仍可能错
- **音频不出扩展**：全链路本地推理，不联网、不留音频。与「不自带编码模型」同一条原则——所谓内置，是内置在用户机器上

### 5.5 已知限制

| 限制 | 后果 | 处理 |
|---|---|---|
| 麦克风权限须在可见页面授权 | offscreen 内无法弹出权限框 | 首次使用跳转 options 页授权一次，之后持久有效 |
| 扩展重载或浏览器关闭 | 模型需重新加载 | 加载进度显示在浮窗，不阻塞交互 |
| 与页面自身音频争用 | 部分页面播放会被中断 | 不做规避，在文档中告知用户 |

## 6. 三层协议

### 6.1 ① ↔ ②：本地 WS + 双重鉴权

**该层必须鉴权，否则任意网页均可连接本地服务并修改源码。**

```
1) Origin 校验：仅接受 chrome-extension://<固定扩展ID>
2) 配对 token：首次由②在终端输出，粘贴至扩展 options，此后每次握手携带
```

Origin 可拦截恶意网页（浏览器会强制设置真实 Origin），token 可拦截本机其他程序。

### 6.2 任务对象（① → ②）

```json
{
  "taskId": "t_01H...",
  "page": { "url": "...", "route": "/user/profile", "title": "用户资料" },
  "target": {
    "sourceLoc": "src/components/ProfileHeader.vue:45:7",
    "selector": "button.edit-btn",
    "text": "编辑资料",
    "rect": { "x": 120, "y": 300, "w": 80, "h": 32 }
  },
  "instruction": { "text": "改成绿色，字号大一点", "source": "voice", "raw": "呃…就是那个按钮，把它弄绿一点" },
  "traces": [{ "trace_id": "tr-b2c4e", "captured_at": "..." }],
  "logs": [{ "level": "WARN", "method": "PUT", "path": "/api/user/profile", "status": 422 }]
}
```

保留 `raw`（口述原话）有实际价值：Agent 可从原话中读出被规则清洗掉的信息。

### 6.3 状态回传（② → ①）

```json
{ "taskId": "...", "phase": "thinking|patching|verifying|applied|failed",
  "message": "正在改 ProfileHeader.vue:45", "diffSummary": "3 行变更" }
```

浮窗按 `phase` 展示进度，`failed` 状态显示原因与回滚结果。

### 6.4 ② ↔ ③：授权边界

仅读写 Vite `root` 目录内文件；拒绝 `.env*`、`*.pem`、`.git/` 及 `../` 路径穿越；每次写盘前创建快照。

## 7. WebGIS 项目限制

若目标项目为 WebGIS，需提前说明：它会改变"点选"这一前提。

地图主体（Cesium / Mapbox GL / Leaflet / OpenLayers）由 **canvas / WebGL 渲染**，不属于 DOM：

```
elementFromPoint 落在地图上 → 只能获取 <canvas> 本身
                           → 无法获取地图中的道路、图标、弹窗
```

可选择的仅有 **DOM 覆盖层**：marker、popup、tooltip、图例、控件、面板。这些通常正是需要修改的 UI 层，因此并非完全不可行。

处理策略：

| 对象 | 是否可选 | 方案 |
|---|---|---|
| UI 覆盖层（图例/控件/弹窗） | 可 | 正常选取，`data-ait` 生效 |
| marker / 标注（DOM 实现） | 可 | 可选，但多为动态创建，无 `data-ait` → 依据 selector 与文本 |
| canvas 内图元（道路/建筑/轨迹） | 不可 | **须由插件在地图实例上挂载调试句柄**：`window.__AIT_MAP__.pickAt(x, y)` → 返回图层与要素 id |

即：若需支持图元级修改，②需识别项目所使用的地图库（在插件中按库名探测实例）。此项为额外工作量，建议后期实现，先覆盖 UI 层。

## 8. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| **M1** | 扩展骨架 + 浮窗四态 + 画圈 + `npx ait` 装配 | 一条命令跑起本地桥，画圈可命中，浮窗不遮挡交互 |
| **M2** | `data-ait` 编译期注入 + 语义匹配 | 圈中任意元素可输出准确 `文件:行号` |
| **M3** | sherpa-onnx 接入：KWS 唤醒 + VAD 端点 + 流式 ASR + 热词 | 说「点睛点睛」唤起，句末输出完整文本 |
| **M4** | 草稿编号 + 自然语言命令 + 提交词 | 可删除指定句、可替换内容、可提交 |
| **M5** | 通道适配（ACP / MCP）+ PatchGate + HMR 验证 | 说「开始改」后页面实际更新；Trae 中可拉到上下文 |
| **M6** | 日志关联 + trace id（需后端配合） | 422 错误可被准确带入上下文 |

M1 与 M2 即可验证产品是否成立：一旦实现"一条命令跑起来 + 画圈输出准确文件行号"，其余均为工程实现。
