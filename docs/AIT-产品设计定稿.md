# AIT（指点江山）· 产品设计 v6.2

> 技术架构见 `AIT-架构定稿.md`。

---

## 1. 定位

**语音 + 鼠标指向。画个圈，说一句，由它定位源码、修改、校验、热更新。**

边界：面向**有源码、以开发模式运行**的项目，不修改第三方生产站点。模型由用户已装的 Agent 提供，AIT 不内置、不持密钥。

---

## 2. 设计理念

以下五条服务于同一目标：**把一次修改的操作路径压到最短**。

### 2.1 组件分工

组件按职能分为三部分：手缩小范围，嘴在其中命中，浮窗负责反馈。

```
鼠标 → 画圈缩小范围：400 个元素缩到 20 个候选   ·  0.20
语音 → 在候选内语义命中，并承载全部指令输入      ·  0.65
浮窗 → 人与插件互动的唯一接口：状态、草稿、候选项
```

候选集内部排序另计视觉显著性 0.15，仅决定列出顺序。详细规则见 §4（交互）与 §5（浮窗）。

### 2.2 鼠标：指向无副作用

最自然的指向动作是点击，但点击会触发表单提交、页面跳转或接口请求。指出"要改哪一个"本身不应产生业务副作用。

因此指向被设计为非触发动作：画圈全程只有一次 `mousedown` + `mouseup`，**没有 `click` 事件**，且仅在唤醒后的 8 秒内生效。

### 2.3 语音：草稿优先，理解口语

**草稿优先。** 语音输入的主要障碍并非识别率，而是出错后的修正成本。该问题不解决，用户不会主动使用。

因此界面核心不是识别，而是**草稿**：内容先落为可编辑文本，可修改、删除或整段丢弃，确认后才提交。缺少草稿态，语音输入只是低效的输入方式。

**理解自然语言。** 用户会描述"那个绿色的按钮"，而不会使用选择器；表达中含冗余、改口与重复，属于正常口语特征。

落到三处：语义匹配（`textContent` → `aria-label` → `placeholder` → `role` → 类名）、口语静默清洗、投递时固定附带"以下为口述内容，请按意图理解"。

**识别在本机。** 语音不出设备：端点检测、唤醒、识别全在端侧 ONNX Runtime 上跑（sherpa-onnx），不联网、不持密钥、不留音频。这与"模型由用户提供"是同一条原则——AIT 不拥有任何数据。

### 2.4 浮窗：人与插件互动的唯一接口

浮窗不是通知，是这台插件的屏幕。零键盘下，它也是唯一能被人"说"着操作的面板。

**没命中就给候选。** 语义匹配不唯一时不追问、不报错，浮窗按分数列出编号候选（最多 5 个），说"第几个 / 第二个"直接锁定，全程不需要点。

| 情形 | 浮窗呈现 |
|---|---|
| 圈内命中唯一 | 直接锁定，显示 `名称 · :行号` |
| 圈内命中多个 | 列编号候选，说"第几个" |
| 圈内没有 | 「圈里没有，是指圈外的『编辑按钮』吗」 |
| 圈内圈外都没有 | 列出附近面积最大的 3 个元素，编号待选 |

由此确定：一个固定词（开始改）、一种强调色、一个固定位置、文案不超过 14 字。

零键盘场景下，失败路径同样必须给出下一步：

| 失败 | 改为 |
|---|---|
| 未能识别意图 | 作为新句追加（可再说「这句不要」） |
| 元素已消失 | 保留 selector，提示「刚才那个元素不在了」 |
| 投递失败 | 复制到剪贴板并显示原因 |

**不静默失败，不弹模态窗，不打断当前操作。**

### 2.5 输入源可替换

目标形态是纯语音，后续可能取消鼠标。抽象层因此按轨迹设计，不绑定鼠标事件：

```ts
interface PointerTrace {
  source: 'mouse' | 'gaze' | 'gesture' | 'remote';
  points: Array<{ x: number; y: number; t: number }>;
  confidence: number;
}
```

新增空中手势或眼动只需实现该接口，交互层不改。

## 3. 整体设计

### 3.1 形态

```
  麦克风（音频流）                    鼠标 / 手势（画圈轨迹，无点击）
        │                                    │
        ▼                                    ▼
┌─ Chrome ─────────────────────────────────────────────────┐
│                                                          │
│ ① AIT 扩展（本插件）                                    │
│   ├ offscreen document：WebAudio + sherpa-onnx           │
│   └ content script    ：画圈 · 浮窗 · DOM 采集           │
│                                                          │
│ 前端页面：dev server 输出，DOM 带 data-ait               │
│                                                          │
└────────────────────────┬─────────────────────────────────┘
                         │ WS + 配对 token
                         ▼
 ② 本地桥（npx ait）· 源码映射 · 提示词 · 通道适配
                         │
              ┌──────────┴──────────┐
               ACP ▼           ▼ MCP
               WorkBuddy   Trae / Cursor / Claude Code
              └──────────┬──────────┘
                         ▼ 改源码
    ③ 前端工程（Vite）── HMR ──▶ 前端页面热更新
```

**输入只有两路**：麦克风进 ① 的 offscreen（音频不出扩展），鼠标事件由 content script 接收（仅轨迹，无 `click`）。**输出只有一路**：Agent 改的是 ③ 的源码，页面更新由 Vite 的 HMR 推回，① 不直接改样式。

**不做桌面应用**：读源码、执行 `tsc`、创建 git 快照、读取日志等能力属于本地桥，而非独立 GUI 应用。它无需安装界面、无需开机自启、无需托盘。

### 3.2 三层职责

| 层 | 做 | **不做** |
|---|---|---|
| ① 扩展 | 画圈、DOM 采集、端侧语音（sherpa-onnx）、浮窗、trace id 注入 | 不读写源码、不执行命令、不持有任务状态 |
| ② 本地桥 | DOM→源码映射、日志关联、提示词组装、通道适配、应用补丁、执行校验 | 不做 UI、不访问麦克风、不内置模型 |
| ③ 前端工程 | 源码、HMR、测试 | — |

### 3.3 两个状态域

| 状态域 | 内容 | 位置 | 理由 |
|---|---|---|---|
| **交互状态** | 待机 / 聆听 / 草稿 / 提交中 | ① 的 offscreen document | 由语音驱动，音频流在此 |
| **任务状态** | thinking / patching / verifying / applied / failed | ② | 任务生命周期本就位于② |

二者以 `taskId` 关联。**①因此可随时刷新重连而不丢失任务**——它不持有任务状态。

### 3.4 三条 Agent 通道

扩展无法作为 MCP server（stdio 与端口监听均无法提供），因此②承担全部通道适配。三条通道按能力递减：

| Agent | 通道 | 体验 | 前提 |
|---|---|---|---|
| **WorkBuddy** | ACP 直连 `127.0.0.1`，主动投递 | 说「开始改」后消息直接出现在对话中 | 需有活跃会话，空闲会被回收 |
| **Trae / Cursor / Claude Code** | ② 作为 MCP server，Agent 主动拉取 | 说一句固定话术「按我选的改」触发 | 用户已配好 MCP（由 `npx ait` 自动写入） |
| 任意 Agent | 剪贴板 + Skill | 手动粘贴一次 | 无需任何配置 |

**通道差异必须如实呈现**：只有 WorkBuddy 能做到真正推送，其余两家受限于客户端不开放注入接口，只能等 Agent 拉取。不做模拟键盘等非官方的注入手段。

### 3.5 语音栈：端侧四件套

语音全部在 ① 的 offscreen 里完成，用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0，ONNX Runtime 推理，支持浏览器 WebAssembly）。

选它的理由不是"模型多"，而是**它不是一个大而全的语音 SDK，而是几个可独立替换的部件**——AIT 需要的正是"端点、唤醒、识别、术语"四件事各自可控。

| 部件 | 用什么 | 在 AIT 里管什么 |
|---|---|---|
| VAD | silero-vad | 判断句末：700ms 静音由端点检测触发，不再是定时器等满 |
| KWS | 开放词表关键词检测 | 待机时只跑 KWS，"点睛点睛"命中才启动 ASR |
| ASR | 流式 Zipformer（14M 中英）/ SenseVoice | 句末整句输出；轻量优先 Zipformer，准度优先 SenseVoice |
| 热词 | contextual biasing | 组件名、字段名进热词表，`useState`、`ProfileHeader` 不靠模型猜 |

由此确定三条：

- **音频不出扩展**。全链路本地推理，不联网、不持密钥、不留音频。与"不自带编码模型、不持密钥"是同一原则——语音模型的内置，是内置在用户机器上。
- **模型即配置**。换模型只换文件，不改代码；轻量与准确可按机器性能切换，不对某个模型做长期承诺。
- **常驻监听只跑 KWS**。VAD + KWS 是低功耗部件，ASR 只在唤醒后启动——这是"一直听着"能成立的前提。

代价同样明确：首次需下载模型（百 MB 级），首次加载有数秒；int8 量化有精度损失，未进热词表的标识符仍可能识别错。

## 4. 交互设计

### 4.1 主流程

```
待机（浮窗隐藏）
  │ 说「点睛点睛」
聆听  │ 画圈 + 说「把那个编辑按钮改成绿色」
锁定  │ 描实线框 + 句末上屏进草稿
草稿  │ 继续补充，或说「不要了」清空
执行  │ 说「开始改」→ 浮窗显示 phase 进度
      ▼
完成（diff 摘要）/ 失败（原因 + 已回滚）
```

### 4.2 命令示例

命令不设词表，按日常说法讲即可。一次典型对话：

```
「那个编辑按钮改成绿色」   → 锁定元素，草稿第 1 句
「字号再大一点」          → 草稿第 2 句
「第二条不要」            → 删掉第 2 句
「开始改」               → 提交执行
```

只有「开始改」是固定词：提交是唯一不可逆的动作。其余说错都能改——删错了重说，改错了再改。说「不对」或「停」可随时打断，且在流式识别结果上即时生效。

提交后草稿不清空，转灰保留「已提交 · 撤回？」——零键盘下，误提交只能靠这一手补救。

## 5. 浮窗设计

### 5.1 性质

通知以抢占注意力为目的，浮窗则需长期停在视野内——它是与插件互动的唯一界面。因此采用固定位置、不跟随光标，依赖肌肉记忆：无需寻找，扫一眼即可确认内容位置；需要选择时（候选、草稿），它就是操作面。

这同时缓解注意力争夺：页面上以实线框标出目标，扫一眼即可确认识别结果，无需注视浮窗。

### 5.2 四态

```
① 聆听                    ② 草稿
┌──────────────────────┐  ┌──────────────────────┐
│ ● 聆听中        3.2s │  │ ● 草稿 · 2 句        │
│                      │  │                      │
│   ▁▃▅▇▅▃▁▁▃▅         │  │ 1 这个按钮改成绿色    │
│                      │  │ 2 字号再大一点        │
│                      │  │ ─────────────────    │
│                      │  │ ▣ 编辑资料 · :45     │
│                      │  │ 开始改               │
└──────────────────────┘  └──────────────────────┘

③ 执行                    ④ 完成
┌──────────────────────┐  ┌──────────────────────┐
│ ● 正在改         ▓▓░░│  │ ● 已改好             │
│                      │  │                      │
│ ProfileHeader.vue:45 │  │ 3 行变更              │
│ 校验通过              │  │ 撤回？               │
└──────────────────────┘  └──────────────────────┘
```

**待机时完全隐藏。** 常驻会造成视觉干扰，并持续占用注意力。

### 5.3 规格

| 项 | 值 | 理由 |
|---|---|---|
| 宽度 | 320px 固定 | 变宽遮挡页面，变窄导致折行 |
| 位置 | 右上角，16px | 右下角通常被页面自身的悬浮组件占用 |
| 高度 | 自适应，草稿上限 5 句 | 底边固定，避免闪烁 |
| 背景 | 深色半透明 + 毛玻璃 | 需覆盖任意页面内容 |
| 字号 | 13px / 1.5 | 余光可读的最小值 |
| 强调色 | 一种（蓝） | 多色意味着多语义，增加认知负担 |
| 动画 | 仅淡入与波形 | **余光难以辨识动画状态**，状态须以静态形状与颜色区分 |
| 图层 | shadow DOM + `pointer-events: none` | 天然点击穿透；位于 shadow 内，不会被 `elementFromPoint` 命中自身 |

### 5.4 文案

第二人称、陈述句、不超过 14 字；**不使用"抱歉"**（致歉属于噪声）。

| 场景 | 文案 |
|---|---|
| 已锁定 | {名称} · :{行号} |
| 圈外更优 | 圈里没有，是指圈外的"{名称}"吗 |
| 找到多个 | 找到 {n} 个，说"第几个" |
| 草稿为空时提交 | 还没有要改的内容 |
| 执行中 | 正在改 {文件名}:{行号} |
| 完成 | 已改好 · {n} 行变更 · 撤回？ |
| 校验失败 | 改完有错，已回滚 · {原因} |
| 投递失败 | 发送失败，已复制到剪贴板 |
| 元素消失 | 刚才那个元素不在了 |

## 6. 已知取舍

以下为当前设计已接受的代价，不属于待办优化项。

| 取舍 | 代价 | 接受理由 |
|---|---|---|
| 仅在浏览器内工作 | 切换至 IDE 后无浮窗与语音 | 主要工作场景在浏览器；②在本地运行，后续可补 CLI |
| 端侧模型需下载 | 首次安装多出百 MB 级模型，加载数秒 | 换音频不出设备、离线可用、零服务费 |
| int8 量化 | 有精度损失，未进热词表的标识符仍可能错 | 热词表兜底，草稿可改，投递前肉眼可见 |
| 仅支持 Vite | webpack / Vue CLI 项目需另写插件 | 首个版本聚焦 Vite，插件结构一致，后续可扩展 |
| **仅 WorkBuddy 可主动推送** | Trae / Cursor / Claude Code 需说一句固定话术触发 | 客户端不开放注入接口，模拟键盘等非官方手段不做 |
| 不自带编码模型 | 用户需自备一个 Agent（语音模型则端侧内置） | 零密钥、零推理成本、不锁定厂商 |
| 说话过程中不可见文本 | 依赖草稿编辑修正（如「第二条不要」） | 实时纠错成本高于收益 |
| 画圈需一次拖动 | 非纯零点击 | 无 `click` 事件、无副作用，且可平滑升级为手势 |
| 首次需装配 | 一次终端命令 + 两次点击 | 终端命令无法用语音替代 |
| 只有一个固定词 | 仅「开始改」精确匹配，其余靠自然语言理解 | 提交不可逆，其余说错都能改 |
| canvas / WebGL 内容不可选 | 地图图元、图表数据点无法指向 | 仅能选择 DOM 覆盖层；图元级需 ② 挂载地图实例（后期） |

## 7. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| **M1** | 扩展骨架 + 浮窗四态 + 画圈 + `npx ait` 装配 | 一条命令跑起本地桥，画圈可命中，浮窗不遮挡交互 |
| **M2** | `data-ait` 编译期注入 + 语义匹配 | **圈中任意元素可输出准确 `文件:行号`** |
| **M3** | sherpa-onnx 接入：KWS 唤醒 + VAD 端点 + 流式 ASR + 热词 | 说「点睛点睛」唤起，句末输出完整文本 |
| **M4** | 草稿编号 + 自然语言命令 + 提交词 | 可删除指定句、可替换内容、可提交 |
| **M5** | 通道适配（ACP / MCP）+ PatchGate + HMR | **说「开始改」后页面实际更新；Trae 中可拉到上下文** |
| **M6** | 日志关联 + trace id | 422 错误可被准确带入上下文 |

**M1 与 M2 决定产品是否成立**：一旦实现"一条命令跑起来 + 画圈输出准确文件行号"，其余均为工程实现。

M2 可在无语音条件下验证：以文本框模拟语音输入，先校准画圈与语义匹配。

## 8. 待定

1. **浮窗位置**：暂定右上角；若实际使用中遮挡内容，改为贴右缘垂直居中
2. **闭合圆与单线划过**：M1 同时实现两种，实测后保留一种
3. **唤醒词**「点睛点睛」：用 KWS 开放词表直接配，无需训练模型；先零样本运行 3-7 天，误唤醒 >3 次/天 或漏唤醒 >20% 再调阈值或换词
4. **扩展是否内置试玩模式**：不连本地桥时可直接改当前页面样式（刷新失效），用于商店演示与体验引导
